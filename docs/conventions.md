# Conventions

## Boundaries
- Layering is enforced by `tests/AdaptOrDeity.ArchitectureTests`: a project may only reference
  projects in a lower layer; `Sim.*` never references `Game.*`; nothing outside `unity/` references
  UnityEngine. Add every new project to the layer table in `DependencyRuleTests.cs`.
- Unity code only talks to `Game.Session`. It never reaches into `Sim.*` state directly.

## Physiology lives upstream
- Physiological equations are CellML modules in `circulatory-autogen-modules`, validated with
  `cam_testing`. C# owns only spatial transport, mechanics and game logic.
- A physiological equation written natively in C# needs an ADR and a reference test.
- Files under `src/AdaptOrDeity.Sim.Kernels.Generated/Kernels/` are generated by `tools/kernelgen`.
  Never edit them by hand; regenerate.
- CellML variable names are kept unchanged in descriptors, saves and probes
  (addressed as `cell:<id>/<module>@<version>/<variable>`).

## Units
- Everything in the simulation is canonical SI as `double`: m, m², m³, s, mol, mol/m³ (= mM), mol/s,
  K, W, J. State the unit in the doc comment, not the identifier.
- Display units (µm, µM, mmHg, °C) are converted only in `Game.Session` / UI.

## Hot paths (anything called per step)
- No allocation, no LINQ, no boxing. Structure-of-arrays (`double[]` per variable).
- Parallelism only through the sim job pool with fixed chunking and ordered reductions, so results are
  bit-identical regardless of thread count.

## Code style
- C# 9 in shipped assemblies (Unity 6 compatibility); tests may use newer C#.
- Nullable enabled, warnings are errors, block-scoped namespaces, `_camelCase` private fields.
- Data (cell types, regions, competitors, fitness weights) lives in `content/` JSON, validated by schema.

## Process
- Cross-cutting choices get an ADR in `docs/adr/NNNN-title.md` (context, decision, consequences).
- Every PR: tests green, goldens updated if kernels changed, units checked, ADR if needed, Unity
  screenshot for UI changes.
