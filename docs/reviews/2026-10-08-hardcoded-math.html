What it does

A regulation law: building new protein and growth run at full speed at the resting ATP (9.6 mM) and stop at 4 mM, linearly between. Capacity 1x the resting ATP turnover. Added because without it building or growth crashed ATP to 0.1-0.7 mM and starved the pumps.

Should it be hardcoded?

This is physiology (how a cell allocates ATP), so by the project rule it belongs in CellML: e.g. an ATP-dependent factor in protein_expression (J_build) and biosynthesis (J_growth), replacing the current ATP/(0.1 mM + ATP) factor, with its parameters sourced or flagged. It is in C# now only because J_build and J_growth are game inputs. The linear ramp and the 4 mM floor are placeholders.

            // Expression moves towards its target; building the extra copies is limited by the build capacity and slows
            // as ATP runs out (f_ATP), so the copies gained scale with the ATP actually spent.
            double build = 0.0;
            double relax = 1.0 - Math.Exp(-dt / ExpressionTimeConstant);
            for (int i = 0; i < Traits.Count; i++)
            {
                _planned[i] = 0.0;
                if (_value[i] == _target[i])
                    continue;
                double next = _value[i] + (_target[i] - _value[i]) * relax;
                if (Math.Abs(next - _target[i]) < 1e-9 * _target[i])
                    next = _target[i];
                _planned[i] = next - _value[i];
                if (_planned[i] > 0.0)
                    build += _planned[i] * _buildPerUnit[i];
            }
            // Build no faster than the build capacity, and back off as ATP falls below rest (the stringent response):
            // full speed at the resting ATP, none at BuildAtpFloor, so building never starves the cell.
            double atp = Batch.States[_sAtp][0];
            double throttle = Math.Min(1.0, Math.Max(0.0, (atp - FermenterTraits.BuildAtpFloor) / (_atpRest - FermenterTraits.BuildAtpFloor)));
            double cap = FermenterTraits.BuildCapacity * RestingTurnover * dt * throttle;
            Batch.Externals[_jGrowth][0] = Math.Max(0.0, GrowthFraction) * RestingTurnover * throttle;
            double scale = build > cap ? (build > 0.0 ? cap / build : 0.0) : 1.0;
            Batch.Externals[_jBuild][0] = build * scale / dt;

What it does

Each step the multiplier moves (target - value)(1 - exp(-dt/tau)) towards its target; the ATP for the copies gained is (delta m) x n L (c_syn + c_poly) / N_A, capped by the throttled build capacity, and copies gained afterwards are scaled by the ATP factor f actually achieved.

Should it be hardcoded?

The cost per copy duplicates protein_expression's M_build = n L (c_syn + c_poly) / N_A (same parameters, read from the kernel, so it cannot drift numerically, but it is the same formula written twice). Cleaner: give protein_expression a state for the expression level per protein (d m/dt = (target - m)/tau, limited) and let it compute J_build itself; the game would then set only the targets. The no-refund rule for decreasing expression (degraded protein is recycled) is a modelling choice to confirm.

        /// <summary>
        /// Pushes each group's controls to its cells: features that are locked or off contribute nothing, and a full group
        /// with a fixed size spends its growth share on repair instead.
        /// </summary>
        private void ApplyControls()
        {
            bool growthOn = Active(GameFeatures.GrowthAndDivision), storageOn = Active(GameFeatures.GlycogenStorage);
            bool repairOn = Active(GameFeatures.RepairLevel), fixedSize = Active(GameFeatures.FixedBodySize);
            for (int i = 0; i < _cells.Count; i++)
            {
                var g = _groups[_cellGroup[i]];
                double growth = growthOn ? g.Controls[GrowthControl] : 0.0;
                double repair = repairOn ? g.Controls[RepairControl] : 1.0;
                if (fixedSize && AliveIn(_cellGroup[i]) >= g.FixedSize)
                {
                    repair = Math.Min(1.0, repair + growth);
                    growth = 0.0;
                }
                var c = _cells[i];
                c.GrowthFraction = growth;
                c.StorageAllocation = storageOn ? g.Controls[StorageControl] : 0.0;
                c.RepairLevel = repair;

What it does

With the fixed-size feature on and the group at its size, the growth share is added to the repair level (capped at 1) and growth is set to 0; daughters replace dead cells in their slot.

Should it be hardcoded?

A game rule, so C#; but repair + growth adds a multiple of ATP turnover (0-2) to a 0-1 level, units that do not match. A cleaner rule would turn the growth ATP into extra repair ATP. Your call on the intended behaviour.

            // out of those packets. Glucose crosses the membrane through the cell's own carriers (Glf) in the kernel.
            _food.Step(dt);
            int nt = _food.TraceSpecies.Count;
            if (_traceAtCell.Length < _cells.Count * nt)

            {

                double c = _food.GlucoseAt(x, y, CellRadius);
                _cells[i].SetExternal("C_glc_e_mod_membrane_face", c);
                for (int tr = 0; tr < nt; tr++)
                    _traceAtCell[i * nt + tr] = _food.TraceAt(tr, x, y, CellRadius);
            }
            for (int i = 0; i < _cells.Count; i++)
            {
                _cells[i].Step(dt);
                double c = _cells[i].External("C_glc_e_mod_membrane_face");
                double uptake = _cells[i].AlgebraicValue("membrane_face__J_glc") * dt;   // mol into the cell
                if (c > _food.BackgroundGlucose && uptake > 0.0)

What it does

Each step a cell's outside glucose is set to background + the summed concentration of the packets it overlaps (no gradient inside a packet, contact = discs overlapping). After the step, the share (c - background)/c of its uptake is taken out of those packets, split by what each holds; the rest is assumed to come from the background, which is never depleted.

Should it be hardcoded?

Exchange between the environment and cells is native transport by design (ADR 0002), so C# is the right place; this is a stand-in for the environment field of the transport graph. Approximations to accept or replace: uniform packets, instant contact (no diffusion across a gap), the background as an infinite reservoir, lactate exported into nowhere, and the (c - b)/c attribution (exact only for uptake linear in concentration; the Glf carrier saturates at 4.1 mM, so packets are charged slightly too little). Glucose is conserved between cell and packet to within that attribution.

        private void Spawn()
        {
            FoodPacket? slot = null;
            foreach (var p in _packets)
                if (!p.Active)
                {
                    slot = p;
                    break;
                }
            if (slot == null)
                return;
            // Enter from a random point on a random side, heading inwards within ±45° of the normal.
            int side = _random.Next(4);
            double along = (2.0 * _random.NextDouble() - 1.0) * HalfSize;
            double edge = HalfSize + PacketRadius;
            double angle = (_random.NextDouble() - 0.5) * Math.PI / 2;
            double nx = 0, ny = 0;
            switch (side)
            {
                case 0: slot.X = -edge; slot.Y = along; nx = 1; break;
                case 1: slot.X = edge; slot.Y = along; nx = -1; break;
                case 2: slot.X = along; slot.Y = -edge; ny = 1; break;
                default: slot.X = along; slot.Y = edge; ny = -1; break;
            }
            double c = Math.Cos(angle), s = Math.Sin(angle);
            slot.Vx = DriftSpeed * (nx * c - ny * s);
            slot.Vy = DriftSpeed * (nx * s + ny * c);
            slot.Radius = PacketRadius;
            slot.Glucose = PacketGlucose * PacketVolume;
            slot.MainTrace = _random.Next(TraceSpecies.Count);
            for (int i = 0; i < slot.Traces.Length; i++)
                slot.Traces[i] = PacketTrace * PacketVolume * (i == slot.MainTrace ? 1.0 : 0.1);
            slot.Active = true;
        }

What it does

Packets enter from a random point on a random side, heading inward within ±45°, at 0.05 um/s, at exponentially distributed intervals (mean 300 s); 10 mM glucose, one main trace at 10 uM and the others at 1 uM. Seeded random, so runs are deterministic.

        public int StepRobust(IKernel kernel, KernelBatch batch, double t, double dt, int start, int end, int maxHalvings = 12)
        {
            int n = batch.States.Length;
            if (_save.Length < n)
                _save = new double[n];
            int worst = 0;
            for (int k = start; k < end; k++)
            {
                for (int i = 0; i < n; i++)
                    _save[i] = batch.States[i][k];
                int halvings = 0;
                while (true)
                {
                    int sub = 1 << halvings;
                    double h = dt / sub;
                    bool ok = true;
                    for (int j = 0; j < sub && ok; j++)
                    {
                        Step(kernel, batch, t + j * h, h, k, k + 1);
                        ok = LastConverged && Finite(batch, k, n);
                    }
                    if (ok || halvings >= maxHalvings)
                        break;
                    for (int i = 0; i < n; i++)
                        batch.States[i][k] = _save[i];
                    halvings++;
                }
                worst = Math.Max(worst, halvings);
            }
            kernel.ComputeVariables(t + dt, batch, start, end);
            return worst;
        }

What it does

Implicit Euler with Newton (tolerance 1e-10 on the scaled update, FD step 1e-7 relative), retried with halved substeps up to 2^12 when Newton fails or a state is not finite.

Should it be hardcoded?

Numerics, independent of the model. Verified against Myokit/CVODE goldens (rest exact, famine NRMSE <= 4e-4).

def _restore_literal_units(components, units, modules_root: Path, supermodule_config: Path) -> None:
    """Give each literal in a submodule's equations the units it has in the source module.

    libcuflynx renames units while flattening and, for some conversion factors, attaches the inverse or a dimensionless
    unit to the number (e.g. 1e-18 tagged um3_per_m3 for m3_per_um3), which leaves the flat model unit-inconsistent.
    The literals of each submodule appear in the same order as in its source file, so units are restored by position;
    the values must agree, or flattening stops.
    """
    known = {u.get("name") for u in units}
    cfg = json.loads(supermodule_config.read_text())[0]
    for sub in cfg["submodules"]:
        comp = components.get(f"mod_{sub['name']}_module")
        if comp is None:
            continue
        matches = [d for d in modules_root.rglob(f"{sub['module_type']}_{sub['module_subtype']}_modules.cellml")
                   if d.parent.name == sub["module_subtype"]]
        if len(matches) != 1:
            raise ValueError(f"source of {sub['name']}: found {matches}")
        src = ET.parse(matches[0]).getroot()
        src_cn = [c for c in src.iter() if c.tag.endswith("}cn")]
        flat_cn = [c for m in comp.findall(f"{{{MATHML}}}math") for c in m.iter(f"{{{MATHML}}}cn")]
        if len(src_cn) != len(flat_cn):
            raise ValueError(f"{sub['name']}: {len(src_cn)} literals in the source, {len(flat_cn)} in the flat model")
        def value(c):
            parts = [t.strip() for t in c.itertext() if t.strip()]
            return float(parts[0]) * 10 ** float(parts[1]) if len(parts) == 2 else float(parts[0])
        unit_attr = [k for k in ("units", f"{{{CELLML}}}units")]
        src_units_file = matches[0].with_name(matches[0].name.replace("_modules.cellml", "_units.cellml"))
        src_units = {u.get("name"): u for u in ET.parse(src_units_file).getroot() if u.tag.endswith("}units")}
        for a, b in zip(src_cn, flat_cn):
            va, vb = value(a), value(b)
            if abs(va - vb) > 1e-12 * max(abs(va), abs(vb), 1e-300):
                raise ValueError(f"{sub['name']}: literal {va} in the source but {vb} in the flat model")
            ua = next(a.get(k) for k in a.attrib if k.endswith("units"))
            kb = next(k for k in b.attrib if k.endswith("units"))
            b.set(kb, ua)

What it does

libcuflynx relabels some conversion-factor literals with wrong units; kernelgen takes each literal's units from the source module by position, checking the values match.

Should it be hardcoded?

Tooling workaround for an upstream bug (open question 11). No math is changed, only unit labels.
